                          HOW TO RUN LOCALLY
================================================================================

QUICK START (2 minutes)
─────────────────────────────────────────────────────────────────────────────

1. Read QUICK_START.md (all steps)

2. Setup:
   powershell -ExecutionPolicy Bypass -File setup-dev.ps1

3. Fill .env with credentials (Supabase, OpenAI, Pinecone)

4. Terminal 1 (Backend):
   cd backend && npm run dev
   # Expected: "LexOS API running on port 4000"

5. Terminal 2 (Frontend):
   cd frontend && npm run dev
   # Expected: "Local: http://localhost:5173"

6. Open browser to http://localhost:5173
   → RAG Module 4 interface ready for testing

================================================================================
                            KEY DECISIONS
================================================================================

✅ TECHNOLOGY CHOICES
   • Node.js/Express over Python → JavaScript fullstack, quicker iteration
   • PostgreSQL over NoSQL → ACID, RLS, relational data (expedientes)
   • Pinecone over Weaviate → Managed service, better for MVP
   • Tailwind over styled-components → Utility-first, dark mode built-in
   • Supabase Auth over custom → Reduces boilerplate, includes OAuth

✅ ARCHITECTURE CHOICES
   • Monolithic over microservices → Simpler deployment, RLS at DB level
   • One namespace per tenant in Pinecone → Hard isolation (no data leakage)
   • Query hashing not storing raw text → Privacy-first (no training data)
   • Temperature 0.1 for legal AI → Factual only, no hallucinations
   • Rate limiting on AI routes → Cost control (OpenAI tokens)

✅ SECURITY FIRST
   • AES-256-GCM for PII (not MD5/SHA1) → Industry standard
   • Audit trail insert-only via RLS → GDPR compliance
   • Secrets in env, never in code → 12-factor app
   • JWT + RBAC → Stateless auth, easy scaling
